# 町内会・自治会 会費標準設定仕様

- 確定日: 2026-07-24
- 対象: 町内会・自治会が会員世帯へ請求する会費
- 対象外: el-townが町内会・自治会へ請求するシステム使用料
- 状態: 仕様確定・未実装

## 1. 基本方針

会費標準設定は、次の2種類に分ける。

1. **全団体共通ルール**
   - 団体側で変更できない。
   - 通貨、請求単位、状態管理、履歴保持、Stripe会計処理など、データ整合性に関わる項目を対象とする。
2. **団体へ配布する初期値**
   - 新規団体へコピーする。
   - 団体は規約や総会決議に合わせて変更できる。
   - 標準設定を変更しても、既存団体や作成済み会費へ自動上書きしない。

会費設定の変更と会費請求の作成は別操作とする。標準値または団体設定を保存しただけでは、会員世帯への請求は発生しない。

## 2. 確定する標準値

### 2.1 全団体共通ルール

| 項目 | 確定値・ルール |
|---|---|
| 通貨 | 日本円（JPY） |
| 請求単位 | 1世帯。`resident_rosters.id` 単位 |
| 同一年度の請求 | 1世帯につき1件。`roster_id + fiscal_year` を一意とする |
| 家族の扱い | 世帯主と連携済み家族は同じ会費レコードを閲覧・支払いする |
| 家族が支払った場合 | 世帯共通の入金額・状態を更新し、世帯主と他の家族にも同じ結果を表示する |
| 会費状態 | 未請求、請求中、一部入金、納入済み |
| 領収書 | 全額納入後に会員画面で表示する |
| Stripe決済 | 各団体のConnect Expressアカウントへの直接決済 |
| Stripe手数料 | 会費総額を収入、実手数料を支出科目「支払手数料」へ別計上 |
| 退会後の履歴 | 作成済みの当期会費と入金実績を削除しない |
| 次年度の対象 | 退会確定済み世帯を新規一括請求から除外する |
| 標準変更の影響 | 作成済み請求・入金・領収書・過年度実績を変更しない |

### 2.2 団体へ配布する初期値

| 項目 | 初期値 | 団体変更 |
|---|---:|---|
| 会費名称 | 年会費 | 可 |
| 標準会費額 | 3,000円 | 可 |
| 会計年度開始月 | 4月 | 可 |
| 請求周期 | 年1回 | 可。ただし初期実装は年次請求のみ |
| 標準請求対象 | 請求作成時点の有効な全会員世帯 | 可。名簿から個別選択可能 |
| 手集金 | 有効 | 可 |
| Stripeカード決済 | Connectが利用可能な場合に有効 | 可 |
| Apple Pay・Google Pay | Stripeカード決済の一部として条件を満たす端末に表示 | 個別設定なし |
| 会費収入科目 | 会費 | 可 |
| 納期限 | 標準値なし | 団体が必要に応じて設定 |
| 減免・免除 | 標準適用なし | 団体が対象世帯と金額を個別設定 |

銀行振込とPayPayは団体会費では未実装のため、選択肢に表示しない。実装・本番検証・運用規則の確定後に標準設定へ追加する。

## 3. 世帯主と家族の仕様

- 世帯主による家族登録および家族招待URL発行は行わない。
- 家族は、本人がLINEから新規登録し、世帯主情報との名簿照合に成功した場合だけ空き家族枠へ連携する。
- 家族枠は既存仕様どおり最大2名とする。
- 世帯主と家族は別の認証・LINE連携・退会状態を持つ。
- 会費は個人別ではなく世帯別とし、世帯主と家族で同じ請求額、入金額、入金方法、状態を表示する。
- 未納または一部入金の場合、世帯主・家族のどちらからでも残額を支払える。
- 同一の決済IDは1回だけ計上し、二重Webhookで入金額を増やさない。

## 4. 会費状態

| 画面表示 | 判定 |
|---|---|
| 未請求 | 対象年度の `fee_records` が存在しない |
| 請求中 | 請求額が設定済みで、入金額が0円 |
| 一部入金 | `0 < 入金額 < 請求額` |
| 納入済み | `入金額 >= 請求額` |

- 入金額は手集金額とStripe入金額の合計とする。
- 全額納入後は支払ボタンを非表示にし、領収書を表示する。
- 返金、チャージバック、過入金は元の入金履歴を削除せず、別取引・調整履歴として扱う。専用UIは別仕様とする。

## 5. 年度請求の作成

1. 団体役員が対象年度、会費名称、金額、対象世帯、決済方法を確認する。
2. 全会員世帯または名簿で選択した世帯を対象にする。
3. 実行前に対象件数、請求総額、除外件数、既存請求件数を確認画面へ表示する。
4. 確定操作で対象年度の `fee_records` を作成する。
5. 同じ世帯・年度に既存レコードがある場合は重複作成しない。

既存レコードの扱い:

- 入金0円: 団体役員が明示的に選択した場合だけ請求額を変更できる。
- 一部入金・納入済み: 一括変更の対象外とする。個別訂正と理由・履歴を必須とする。
- 過年度: 標準設定や新年度設定から変更しない。

## 6. 標準設定のバージョン管理

- 公開済み標準設定は上書きせず、新しいバージョンを作成する。
- 状態は `draft`、`published`、`retired` とする。
- 新規団体は登録時点の最新 `published` バージョンを取得する。
- 団体ごとに、適用した標準バージョンと上書き項目を記録する。
- 標準値の変更理由、変更者、公開日時を履歴として保持する。

想定データ:

- `membership_fee_standard_versions`: el-town全体の標準設定
- `neighborhood_fee_settings`: 団体別設定、適用バージョン、上書き項目
- `membership_fee_standard_applications`: 既存団体への適用履歴

テーブル名は実装時に既存DBとの衝突を確認して確定する。団体別会費設定を、システム使用料用の `system_settings` と混在させない。

## 7. 既存団体への反映

標準設定を公開しても既存団体へ自動反映しない。システム管理者が次の手順で適用する。

1. 対象となる団体と変更前後の差分を表示する。
2. 団体独自設定がある項目を「上書きあり」と表示する。
3. 初期状態では、未設定項目だけを適用対象にする。
4. 団体独自設定の上書きは、団体を個別選択し、再確認した場合だけ許可する。
5. 適用対象、除外対象、変更前後、実行者、実行日時、標準バージョンを履歴へ保存する。
6. 作成済みの `fee_records` は一括適用の対象外とする。

## 8. 権限

- システム管理者:
  - 標準設定の下書き、公開、廃止
  - 新規団体向け標準バージョンの指定
  - 既存団体への差分確認付き適用
- 団体役員:
  - 団体変更可能項目の編集
  - 年度会費の請求作成、対象選択、手集金登録
- 会員世帯:
  - 世帯共通の請求・入金状態の閲覧
  - 利用可能な決済方法での支払い
  - 全額納入後の領収書表示

## 9. システム管理画面

「会費標準設定」画面に次を設ける。

- 下書き中・公開中のバージョン
- 全団体共通ルールの参照
- 団体へ配布する初期値の編集
- 変更理由
- 公開前差分
- 新規団体への適用開始
- 既存団体との差分一覧
- 対象団体の選択と除外
- 適用履歴

公開と既存団体への適用は別操作とし、それぞれ確認画面を必須とする。

## 10. 受け入れ条件

1. 新規団体へ最新の公開標準値がコピーされる。
2. 団体役員が変更可能項目を上書きできる。
3. 標準設定を変更しても既存団体・既存請求が自動変更されない。
4. 既存団体へ適用する前に差分と対象件数を確認できる。
5. 世帯主と家族が同じ会費レコードを表示する。
6. 家族が支払った場合も、世帯主と家族全員に納入済み状態が表示される。
7. 全額納入後は全員の支払ボタンが消え、領収書が表示される。
8. Stripe Webhookが再送されても同じ決済を二重計上しない。
9. 退会後も作成済み会費と入金実績が保持される。
10. 標準設定の公開・適用履歴から変更者、日時、変更内容を追跡できる。

## 11. 実装順序

1. DBテーブル、制約、RLS、監査履歴
2. システム管理画面の標準設定・バージョン公開
3. 新規団体への初期値コピー
4. 団体別設定画面と標準値との差分表示
5. 既存団体への差分確認付き一括適用
6. 年度請求作成前の確認画面
7. 世帯主・家族による同一会費表示と決済後反映の結合試験
