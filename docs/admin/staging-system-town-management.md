# 検証用システム管理から町内会管理画面への移動

対象は `el-town-staging`（Supabase Project Ref `zghcorbdtslrjtkkspfe`）のみ。本番サイト・本番DBでは利用しない。

1. `/system` にシステム管理者としてログインする。
2. 町内会・自治会一覧の対象行で「管理画面」を押す。
3. サーバーがシステム管理セッションのCookieと、検証用システム管理者Authユーザーのアクセストークンを両方検証する。対象町内会を確認した後、そのAuthユーザーに該当町内会の `active` な管理者所属を1件だけ付与する。
4. `/admin` で対象町内会を選択して開く。「システム管理へ戻る」で `/system` に戻れる。

所属はDBに残り、ログアウト時に自動削除されない。同じ町内会への再入場では重複作成しない。役員一覧の表示件数・招待上限・最後の役員判定にはシステム管理者を含めない。所属の停止が必要な場合は、検証用DBで対象のシステム管理者行を確認してから処理する。ログアウトは `/system` のCookieとブラウザーのSupabaseセッションを両方終了する。

## 確認結果（2026-10-21）

- 検証用町内会 ID 30 で、Cookieなしの権限付与は401、無効なアクセストークンは403。
- 正しいシステム管理セッションで管理者所属を作成し、再入場後も所属は1件だけ。
- 役員所属API、管理画面データAPI、役員管理APIが200。システム管理一覧の役員表示件数は既存の役員1名のまま。
- 架空の役員招待を作成（201）して削除（200）し、システム管理者からの編集操作と後片付けを確認した。招待メールは送信していない。
- 対象以外のSupabase Project Refや未設定のシステム管理者IDではサーバー側で停止する。

管理画面内にはブラウザーからDBへ直接書き込む旧画面も残っている。検証用ベースラインはその直接書き込みを許可していないため、全機能の編集ができるという意味ではない。ブラウザーでの画面遷移と各画面の編集操作は検証サイトへ公開した後に個別に確認する。公開には `docs/admin/safe-deployment.md` の承認付き手順を使う。
