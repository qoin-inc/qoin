# 検証環境の回覧添付 Storage

対象は `el-town-staging`（Supabase Project ID `zghcorbdtslrjtkkspfe`）。本番SupabaseやNetlifyへの適用は含まない。

## 実装

- 回覧の新規添付は専用の非公開バケット `circular-attachments` に保存し、DBには公開URLではなく `町内会ID/circulars/ファイル名` のパスを記録する。
- 添付のアップロードは、その町内会で `active` の役員に限定する。読み取りは同じ町内会の active 役員と、退会していない紐付け済み会員・有効な家族アカウントに限定する。
- 会員画面は閲覧時に1時間有効の署名付きURLを発行する。期限切れ後は画面を再読み込みして取得し直す。
- 回覧本文の保存は検証環境限定の `/api/admin/circulars` で役員の所属を確認し、町内会IDと入力項目を絞って行う。
- 既存の公開 `attachments` バケットには変更を加えない。同バケットを利用する別の投稿画面への影響を避ける。既存の公開URLも、この変更だけでは非公開にならない。
- 領収書アップロードは現在入力が無効化されているため、今回は有効化しない。

## 適用手順

1. Supabase Dashboard のプロジェクト名と ID が上記と一致することを確認する。
2. [SQL](../../supabase/staging-baseline/20261018_circular_private_storage_STAGING.sql) を検証プロジェクトの SQL Editor で実行する。これはバケット作成と Storage/回覧の RLS ポリシー追加を伴う。
3. 実行結果で `public=false`、`file_size_limit=10485760`、Storage ポリシー数 `2` を確認する。
4. 検証用役員で画像/PDFを添付して回覧を保存し、同じ町内会の会員で閲覧できることを確認する。匿名ユーザーと別町内会の会員では参照できないことを確認する。

## 現時点の制約

- Netlify の検証サイトに未デプロイなら UI からの動作検証はまだできない。SQL適用とコードの静的確認は別々に記録する。
- 添付アップロード後に本文保存が失敗すると、使用されないファイルが残る。定期的な確認と整理が必要。
- LINE通知には非公開添付のURLを渡さない。回覧の本文リンクを案内する。
