# 検証用役員招待 API 結合試験（2026-10-18）

対象は `staging-invite-server` ブランチのローカル Next.js と、Supabase `el-town-staging`（Project Ref `zghcorbdtslrjtkkspfe`）のみ。秘密キー、ログイン情報、招待トークンは記録しない。本番 DB・本番サイト・Netlify デプロイは操作していない。

## 前提

- 検証用のシステム管理者 Auth ユーザーを ID 許可表へ1件登録済み。検証用の一時ログインで管理者判定関数2件が `true`。
- ローカル `.env.local` の接続先と Project Ref が検証用 Project に一致。公開用キーとサーバー秘密キーは異なり、`.env.local` は Git 管理対象外。
- 試験前の検証用 DB は `neighborhoods=0`、`neighborhood_admins=0`、Auth ユーザー1件。

## 実施結果

検証用の町内会と現役役員を一時作成し、架空の招待候補者で API を呼んだ。

| 確認項目 | 結果 |
| --- | --- |
| トークンなしの役員一覧 | 401 で拒否 |
| 所属しない町内会の役員一覧 | 403 で拒否 |
| 所属町内会の役員一覧 | 200、登録済み役員1件 |
| 招待作成 | 201、保留中の役員1件を作成 |
| 招待詳細 | 200、有効な招待と町内会名を確認 |
| 招待削除後の詳細 | 404、利用不可 |
| 招待先とメールが異なるユーザーの受諾 | 403 で拒否 |
| 招待先の架空 Auth ユーザーによる受諾 | 200、役員状態が `active`、Auth ユーザー ID が一致 |
| 受諾後の両招待トークン | `NULL`、同一トークンの再利用は404で拒否 |
| 受諾した役員の一覧取得 | 200、同じ町内会の役員2件を取得 |

試験終了後、テスト用町内会と役員、および一時作成した Auth ユーザーを削除。事後確認は `neighborhoods=0`、`neighborhood_admins=0`、Auth ユーザー1件で、試験前と一致した。

## 残る範囲

管理画面全体のブラウザ経由 DB アクセス、町内会新規登録、Storage、LINE、Stripe、Netlify 上の動作は未検証。役員招待 API 単体の結合試験成功を、アプリ全体の利用可能性と扱わない。
